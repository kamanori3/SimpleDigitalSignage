# クラス設計図（PdfSignage）

現状コード（`PdfSignage/`）から起こしたクラス構成。処理の流れ・ライフサイクルは [設計書.md](設計書.md) を参照する。

- 対象: `PdfSignage` プロジェクトの型（テストプロジェクトは対象外）
- 依存の向き: **View → ViewModel → Services**。Services は View / ViewModel を参照しない
- DI コンテナは使わない。共有は `ApplicationContext.Current`（[ADR 0002](adr/0002-di-コンテナを使わない.md)）

図は Mermaid の `classDiagram`。GitHub / VS Code プレビューで描画できる。

---

## 1. 名前空間と配置

| 名前空間 | フォルダ | 役割 |
|---------|---------|------|
| `PdfSignage` | ルート | `App`（WPF エントリ） |
| `PdfSignage.Views` | `Views/` | ウィンドウ（XAML + code-behind） |
| `PdfSignage.ViewModels` | `ViewModels/` | 画面状態・コマンド |
| `PdfSignage.Models` | `Models/` | 永続化・再生の純粋データ |
| `PdfSignage.Services` | `Services/` | 再生・設定・OS 連携 |
| `PdfSignage.Interop` | `Interop/` | Win32 P/Invoke（`internal`） |

`CachedPdfDocument` と `Win32Native` だけが `internal`。それ以外の型は `public`。

## 4. 起動と画面

### App

```mermaid
classDiagram
  class App {
    +App()
    -Application_Startup(sender, e)
    -OnApplicationExit(sender, e)
  }
```

`App.xaml` の `Startup="Application_Startup"` がエントリ。コンストラクタで `Exit` / `SessionEnding` / `ProcessExit` にタスクバー復元を張る。

### View

```mermaid
classDiagram
  class MainWindow {
    -MainViewModel _viewModel
    -KioskModeService _kioskMode
    -ScheduleService? _scheduleService
    -AdminWindow? _adminWindow
    -bool _isAdminMode
    -bool _adminClosingForKioskReturn
    +MainWindow()
    -ToggleAdminMode()
    -EnterAdminMode()
    -ExitAdminMode()
    -ExitApplication()
    -OnScheduledAppExit()
    -OnScheduledPcShutdown()
    -VideoPlayer_MediaEnded()
    -VideoPlayer_MediaFailed()
  }

  class AdminWindow {
    -AdminViewModel _viewModel
    +AdminWindow(viewModel)
    +event ReturnToKioskRequested
    +event ExitApplicationRequested
  }

  MainWindow --> MainViewModel
  MainWindow --> AdminWindow
  AdminWindow --> AdminViewModel
```

`MainWindow` が View 層で持っている責務（ViewModel に置いていないもの）:

- キオスク枠（`KioskModeService`）
- 日次スケジュール（`ScheduleService`）
- 管理画面の開閉と `Application.Current.Shutdown()`
- `MediaElement` の Play / Stop / MediaEnded / MediaFailed

`AdminWindow` の 2 イベントは `AdminViewModel` の同名イベントへの転送。ショートカット `Ctrl+Shift+M` は `ReturnToKioskCommand` を実行する。

```mermaid
classDiagram

    +int MinDisplaySeconds$ = 5
    +int MaxDisplaySeconds$ = 300
    +int DefaultDisplaySecondsValue$ = 15
    +string WatchFolderPath
    +int DefaultDisplaySeconds
    +bool WindowsAutoStart
    +string? AppExitTime

  class Slide {
    +SlideContentType ContentType
    +string FilePath
    +int PageIndex
    +int DisplaySeconds

  }

  class SlideContentType {
    <<enumeration>>
    Image
    PdfPage
    Video
  }

  Slide --> SlideContentType
```

- `AppSettings` は `settings.json`（camelCase）のスキーマ。範囲定数はここが唯一の定義箇所
- `Slide` は不変（setter なし）。PDF は 1 ページ = 1 `Slide`（`PageIndex` が 0 始まり）
- 動画の `DisplaySeconds` は常に `0`（タイマー進行しない）

## 8. 再生パイプライン

ファイル列挙 → スライド展開 → 描画 → 先読み、の流れ。

```mermaid
classDiagram
  direction TB

  class ContentFolderScanner {
    <<static>>
    +Scan(folderPath)$ IReadOnlyList~string~
    +IsImageFile(filePath)$ bool
    +IsPdfFile(filePath)$ bool
    +IsVideoFile(filePath)$ bool
    +IsContentFile(filePath)$ bool
  }

  class NaturalStringComparer {
    +Instance$ NaturalStringComparer
    +Compare(x, y) int
  }

  class DisplayDurationParser {
    <<static>>
    +Resolve(filePath, defaultSeconds)$ int
    +HasCustomDuration(filePath)$ bool
  }

  class PlaylistBuilder {
    -PdfRenderer _pdfRenderer
    -FileLogger _logger
    -int _defaultDisplaySeconds
    +PlaylistBuilder(pdfRenderer, logger, defaultDisplaySeconds)
    +Build(folderPath, renderWidth, renderHeight) IReadOnlyList~Slide~
  }

  class ContentFolderWatcher {
    +event ContentChanged
    +ContentFolderWatcher(folderPath, logger)
    +Dispose()
  }

  class SlidePreloader {
    +Preload(slideIndex, slides, loadFunc)
    +TryTakePreloaded(slideIndex) ImageSource?
    +Cancel()
    +Dispose()
  }

  class PdfRenderer {
    +PdfRenderer(logger, renderWidth, renderHeight)
    +GetPageCount(pdfFilePath) int
    +RenderPage(pdfFilePath, pageIndex) ImageSource
    +ClearCache()
    +Dispose()
  }

  class CachedPdfDocument {
    <<internal>>
    +string FilePath
    +int PageCount
    +CachedPdfDocument(filePath, renderWidth, renderHeight)
    +RenderPage(pageIndex, logger) ImageSource
    +Dispose()
  }

  class PdfRenderDimensions {
    <<static>>
    +Create(screenWidth, screenHeight)$ PageDimensions
  }

  class ImageLoader {
    <<static>>
    +Load(filePath)$ BitmapImage
  }

  class BitmapSourceHelper {
    <<static>>
    +FromBgra32(pixels, width, height)$ BitmapSource
    +FlattenBgraOnWhite(pixels, width, height)$ BitmapSource
    +CountVisiblePixels(pixels)$ int
  }

  class DisplayRenderHelper {
    <<static>>
    +GetPrimaryScreenSize()$ (int Width, int Height)
  }

  ContentFolderScanner ..> NaturalStringComparer : ソート
  PlaylistBuilder ..> ContentFolderScanner
  PlaylistBuilder ..> DisplayDurationParser
  PlaylistBuilder --> PdfRenderer : GetPageCount
  ContentFolderWatcher ..> ContentFolderScanner : 対象拡張子判定
  PdfRenderer *-- CachedPdfDocument
  CachedPdfDocument ..> PdfRenderDimensions
  CachedPdfDocument ..> BitmapSourceHelper
```

対応形式の定義箇所は `ContentFolderScanner` の 3 配列だけ（`.jpg` / `.jpeg` / `.pdf` / `.mp4`）。形式を足すならここが入口。

`PlaylistBuilder.Build` の `renderWidth` / `renderHeight` はシグネチャに残っているが、実際の寸法は `PdfRenderer` のコンストラクタで既に保持している。ページ数取得のために `PdfRenderer.GetPageCount` を呼ぶと、その時点で `CachedPdfDocument` がキャッシュに入る。

`SlidePreloader` は `MainViewModel.LoadSlideContent` をコールバックとして受け取る。先読み対象は画像と PDF ページのみ。

## 10. 生成と寿命

コード上の `new` と静的初期化の対応。テストから直接 `new` できるのはコンストラクタが公開されている型に限る。

```
App.Application_Startup
  └─ ApplicationContext.Initialize()
        ├─ new SettingsService()
        ├─ SettingsService.Load() → AppSettings
        ├─ PathHelper.Resolve* （フォルダ作成）
        ├─ new FileLogger(logDirectory)
        └─ WindowsAutoStartService.Apply
  └─ new MainWindow()
        ├─ new MainViewModel(ApplicationContext.Current)
        │     ├─ DisplayRenderHelper.GetPrimaryScreenSize()
        │     ├─ new PdfRenderer
        │     ├─ new PlaylistBuilder
        │     ├─ new SlidePreloader
        │     ├─ new ContentFolderWatcher
        │     └─ new DispatcherTimer
        ├─ Loaded
        │     ├─ new KioskModeService().Activate  ※フィールドはコンストラクタで new 済み
        │     └─ new ScheduleService(context).Start()
        └─ EnterAdminMode（Ctrl+Shift+M）
              ├─ new AdminViewModel(context, applySettings)
              └─ new AdminWindow(adminViewModel)
```

静的クラス（インスタンスを持たない）:

`PathHelper` `SettingsValidator` `ContentFolderScanner` `DisplayDurationParser` `ImageLoader` `BitmapSourceHelper` `DisplayRenderHelper` `PdfRenderDimensions` `TaskbarController` `ScheduleTimeHelper` `PcShutdownService` `WindowsAutoStartService` `AppSelfRestartService` `Win32Native`

シングルトン相当:

| 型 | 仕組み |
|----|--------|
| `ApplicationContext` | 静的 `Current`。`Initialize` で一度だけ代入 |
| `NaturalStringComparer` | 静的 `Instance` |
| `AppSelfRestartService` | 静的 Mutex / フラグ |
| `TaskbarController` | 静的参照カウント |

## 11. 単体テストが直接触る型

`PdfSignage.Tests` は外部 I/O や UI を持たない静的ロジックだけを対象にしている。

| テスト | 対象型 |
|--------|--------|
| `ContentFolderScannerTests` | `ContentFolderScanner` |

| `NaturalStringComparerTests` | `NaturalStringComparer` |
| `PathHelperTests` | `PathHelper` |
| `ScheduleTimeHelperTests` | `ScheduleTimeHelper` |

`MainViewModel` / `ApplicationContext` / 各 Window に自動テストは無い。挙動確認は [受け入れテスト.md](受け入れテスト.md)。

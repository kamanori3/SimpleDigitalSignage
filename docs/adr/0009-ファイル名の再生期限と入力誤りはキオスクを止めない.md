# ADR 0009: ファイル名の再生期限と入力誤りはキオスクを止めない

- 状態: 有効
- 日付: 2026-09-12

## 文脈

表示秒数に続き、再生期限もファイル名末尾（`_YYYYMMDD`）で指定できるようにした。秒数との順番は問わず、必ず末尾に付ける。ここで次を決める必要があった。

- 期限日当日は出すのか
- 日付が変わった瞬間に今のスライドを切るのか
- 存在しない日付や秒数の重複を、再生から外すのか
- 誤りをいつ、どこで知らせるのか
- 動画にも期限を適用するのか（秒数は [ADR 0004](0004-動画の表示時間指定を無効にする.md) で無効）

## 決定

- **指定日当日まで再生する。** 翌日 0:00 以降を期限切れとする（`today > expiresOn`）
- 期限切れファイルは削除せず、プレイリストから外すだけにする
- 日付跨ぎの反映はフォルダ変更と同じく、次のスライド境界まで待つ（[ADR 0003](0003-フォルダ変更をスライド境界まで遅延させる.md)）
- **入力誤りは再生を止めない。** 誤った指定だけ捨て、残りを使う（秒数ならデフォルト、日付なら期限なし）
- 誤りの通知はキオスクには出さず、**管理モード入場のたびに** MessageBox を 1 つ出す
- 動画も期限の対象にする。秒数指定は ADR 0004 のまま無効
- `IMG_2716.jpg` のような 4〜7 桁・9 桁以上の末尾数字は、秒数でも日付でもないので無視する（誤りにもしない）
- 対象ファイルがすべて期限切れのときは空フォルダ扱いとする。復帰不能にはしない

## 理由

- 「9 月 4 日まで」は当日いっぱい出すのが日本語の期限の読み方に合う
- 無人の掲示中に MessageBox や即リロードを出すと、読んでいる途中の画面が止まる。フォルダ変更で既に却下した体験と同じ
- 名前の typo でファイルごと消えると、残りの掲示まで空になる。カメラ由来の `IMG_2716` を誤り扱いすると誤報になる
- 管理者が `Ctrl+Shift+M` を開いたタイミングなら、キオスクを止めずに誤りに気づける
- 期限は「出す／出さない」の話なので、動画の長さとは独立している。秒数打ち切りの問題（ADR 0004）は起きない

## 検討した代替案

**期限日の 0:00 から非表示** — 「その日まで」と説明しづらい。却下。

**日付変更の瞬間に即リロード** — 表示中断が起きる。ADR 0003 と同じ理由で却下。

**誤りファイルを再生から外す** — 1 件の typo で掲示が減る／空になる。気づきやすさより継続を優先した。

**キオスク上で即 MessageBox** — 無人運転中にダイアログが残り、ループが止まる。却下。

**ログだけ残す** — コンテンツ担当者はログを見ない。管理モード入場は既にある確認タイミングなので、そこに寄せた。

**管理画面に期限設定 UI を足す** — ファイルを置く運用と二重になる。MVP の「フォルダに置けばよい」を崩す。

**`Slide` に期限を持たせて毎ティック判定する** — 日付跨ぎの再構築と同じ結果になるのに状態が増える。構築時のフィルタで足りる。

## 結果

`DisplayDurationParser` が秒数と期限をまとめて返し、`PlaylistBuilder` が期限切れを除外する。日付跨ぎは `ScheduleService.DateRolledOver` → `_playlistReloadPending`。誤りの本文は `FormatIssuesMessage`、表示は `MainWindow.EnterAdminMode`。

**「ファイルを置いてもすぐ期限切れにならない」「名前を間違えても再生は続く」が仕様になる。** 変えるなら [操作ガイド](../操作ガイド.md) と [運用ガイド](../運用ガイド.md) も直すこと。

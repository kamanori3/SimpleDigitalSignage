# ADR 0012: スタンドアロン商品は監視フォルダをこの PC 内に限定する

- 状態: 有効
- 日付: 2026-09-12

## 文脈

課金方針では、ネット必須にしないスタンドアロン商品と、将来のネットワーク共有対応商品を同じコードベースで出す想定がある。監視フォルダに UNC や割り当てドライブを無制限に書けると、スタンドアロンとして売っているのに施設 LAN の共有へ依存する運用が黙って成立する。一方で、exe を二つに分けると修正が二重になる。

## 決定

`settings.json` の `allowNetworkWatchFolder`（既定 `false`）でゲートする。false のときは UNC と `DriveType.Network` の割り当てドライブを拒否する。管理画面には切替 UI を出さない。保存時は検証エラー、実行時（`settings.json` 直編集含む）は `SignageData` へフォールバックする。

ネットワーク商品は同じ exe のフラグを `true` にするだけ。フラグを外したあとの UNC 本格対応（ログ親階層の書き込み、`FileSystemWatcher` の取りこぼし）は別作業とする。

## 理由

- 商品差を設定 1 行で切り替えられ、コード分岐を SKU ごとに増やさない
- 管理画面に出すと現場がスタンドアロン契約のまま共有運用へ切り替えられる。切替は販売側が配布物の `settings.json` を書く作業に閉じる
- 保存だけ弾いても直編集で抜けられるので、`PathHelper` でも同じ判定を通す

## 検討した代替案

**csproj / インストーラを SKU ごとに分ける** — 同じ修正を二箇所へ入れることになる。件数が少ないうちは過剰。

**管理画面のチェックボックス** — 現場が商品境界を越えられる。ライセンスコード連携までの暫定としても、スタンドアロンの約束と矛盾する。

**UNC だけ拒否し、割り当てドライブは許可** — `Z:\` が共有ならスタンドアロン限定を簡単に迂回できる。

## 結果

ログは監視フォルダの親へ書く（[ADR 0008](0008-ログを監視フォルダの親階層に出力する.md)）。拒否して `SignageData` に落ちたときは、その親の `logs` を使う。フラグを true にしても、読み取り専用共有の親へログを書けない問題は残る。

将来ライセンスコードを入れるときは、プラン検証の結果でこのフラグを上書きできる。今回はフラグだけを置き、公開鍵検証は入れない。

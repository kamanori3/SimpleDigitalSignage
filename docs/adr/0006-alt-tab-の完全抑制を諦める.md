# ADR 0006: Alt+Tab の完全抑制を諦める

- 状態: 有効
- 日付: 2026-08（MVP 開発時の判断を後追いで記録）

## 文脈

要件はキオスクモードとして「Alt+Tab 等によるアプリ切替を可能な範囲で抑制」すること。掲示中に利用者が誤ってデスクトップを表示してしまう状況を避けたい。

Windows では Alt+Tab や Win キーの完全な無効化は、通常のアプリケーション権限では行えない。実現するにはローレベルキーボードフックの常駐、グループポリシー、シェル置き換えといった手段が必要になる。

## 決定

完全抑制は行わない。以下の範囲にとどめる。

- 枠なし全画面（`WindowStyle=None` / `ResizeMode=NoResize`）+ `Topmost`
- タスクバーの非表示（`TaskbarController` 経由の `SHAppBarMessage` / `ShowWindow`）
- ウィンドウに `WS_EX_TOOLWINDOW` を付与し、**Alt+Tab の一覧に自分自身を出さない**

## 理由

- ローレベルキーボードフックは、セキュリティ製品に誤検知されるリスクがある。現場 PC への導入障壁になる
- グループポリシーやシェル置き換えは、アプリ単体で完結せず、現場の PC 管理ポリシーに踏み込む
- 想定利用シーン（大学の就職イベント案内の掲示）では、悪意ある操作ではなく偶発的な操作を防げれば十分
- 抑制を強めるほど、管理者が正規に操作したいときの障害にもなる

## 検討した代替案

**ローレベルキーボードフック（`WH_KEYBOARD_LL`）で Alt+Tab / Win キーを握りつぶす** — 上記のリスクに加え、アプリがハングしたときにキー入力が効かなくなる副作用がある。サイネージ PC が操作不能になる危険が大きい。

**Windows の割り当てられたアクセス（Kiosk Mode）を使う** — OS 機能としては正しい解だが、専用ユーザーアカウントの作成と OS 側の設定が必要で、「exe をコピーして起動するだけ」という配布方針と両立しない。

## 結果

**Alt+Tab を押せば他のアプリへ切り替えられる。** これは仕様であり、[運用ガイド](../運用ガイド.md)の「既知の制限事項」に明記している。

`Topmost` を使っているため、切り替えても本アプリが前面に残りやすい。ただし裏を返すと、管理画面を開く際に `KioskModeService.Deactivate()` で明示的に解除しないと、他のウィンドウが本アプリに隠れる。`MainWindow.EnterAdminMode()` が `Deactivate` → `Hide` の順で呼んでいるのはこのため。

タスクバーを隠している以上、**アプリが異常終了してもタスクバーを必ず戻す**必要がある。`App` のコンストラクタで `SessionEnding` と `ProcessExit` の両方に `TaskbarController.ForceRestore()` を張ってあるのは保険。ここを削るとタスクバーが消えたままの PC が残る。

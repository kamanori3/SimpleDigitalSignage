# ADR 0005: 設定ファイルを exe と同じ場所に置く

- 状態: 有効
- 日付: 2026-08（MVP 開発時の判断を後追いで記録）

## 文脈

`settings.json` の置き場所を決める必要がある。Windows アプリの定石は `%APPDATA%` 配下だが、本アプリはインストーラーを持たないポータブル配布で、「フォルダ一式をコピーして exe を起動する」という運用を前提にしている。

## 決定

`AppContext.BaseDirectory`（exe と同じフォルダ）に `settings.json` を置く。

## 理由

- 配布フォルダをコピーするだけで設定ごと複製できる。複数台のサイネージ PC に同じ設定を配る作業が、フォルダのコピーで完結する
- アンインストールがフォルダの削除で済み、レジストリや `%APPDATA%` に残骸を残さない
- 設定がどこにあるか一目で分かる。現場で管理者がファイルを直接確認・編集できる
- 同梱の `settings.example.json` と並ぶので、テンプレートとして参照しやすい

## 検討した代替案

**`%APPDATA%\PdfSignage\settings.json`** — Windows の作法としては正しく、Program Files 配下にインストールした場合でも書き込める。しかし設定を配布物に含められず、ポータブル運用の利点が消える。

**レジストリ** — 現場の管理者が確認・編集しづらい。

## 結果

**書き込み権限のある場所に配布フォルダを置く必要がある。** `C:\Program Files` 配下に置くと設定を保存できない。運用としては `C:\PdfSignage` や `D:\` 直下などを想定している。

設定の読み込みに失敗したときのログ出力先が問題になる。ログフォルダは監視フォルダから算出するが、その監視フォルダが読めていないため、まだ確定していない。このため `SettingsService.WriteLoadError()` だけは例外的に exe 横の `settings_load_error.log` へ書く。**通常のログとは別の場所なので、障害調査時はここも見る。**

自己再起動（`AppSelfRestartService.Restart()`）で `WorkingDirectory` に `AppContext.BaseDirectory` を指定しているのも、再起動後に同じ設定ファイルを読ませるため。

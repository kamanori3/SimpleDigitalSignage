# ADR 0011: 壊れたファイルも管理モード入場時に知らせる

- 状態: 有効
- 日付: 2026-09-12

## 文脈

壊れた PDF・画像・動画は、プレイリスト構築または表示時にスキップし、他のファイルの再生は続ける。ログには ERROR が残るが、コンテンツ担当者はログを見ない。ファイル名の指定誤りは管理モード入場時の MessageBox で知らせている（[ADR 0009](0009-ファイル名の再生期限と入力誤りはキオスクを止めない.md)）のに、壊れたファイルは画面上では分からない、という差があった。

ここで次を決める必要があった。

- いつ知らせるか
- ファイル名誤りと同じダイアログにまとめるか
- どこまでを「壊れている」と判定するか（コピー途中、動画の中身）

## 決定

- **知らせるタイミングはファイル名誤りと同じ。** キオスク再生中には出さず、管理モード入場のたびに MessageBox を出す。既読管理はしない
- **ダイアログは分ける。** タイトルは「壊れたファイル」。直し方が「名前を直す」と「ファイルを差し替える」で違うため、表示期限の指定とは混ぜない。両方あるときはファイル名誤りを先に出す
- **判定は入場時にフォルダを再スキャンして開けるかを見る。** 再生中のスキップ履歴には依存しない
- 画像は JPEG ヘッダ＋縮小デコード、PDF は `%PDF` ヘッダ＋ページ数取得、動画は ISO BMFF の `ftyp` ボックスまで見る
- 空ファイル・ヘッダ不正・デコード失敗を壊れているとする
- **コピー途中の排他ロックは壊れているとしない**（開けないのは一時的だから）
- 再生はこれまでどおりスキップして続ける。壊れているからといってプレイリスト全体は止めない

## 理由

- 無人の掲示中にダイアログを出すとループが止まる。ADR 0009 と同じ理由
- 管理モード入場は、既に管理者が画面を見ている確認タイミングである
- 1 つの MessageBox に名前の誤りと破損を混ぜると、どちらを直せばよいか分からない
- 動画の完全な再生可否は `MediaFailed` まで分からない。入場時に MediaElement で試すとタイムアウトや UI スレッド待ちが増えるので、コンテナヘッダまでにする

## 検討した代替案

**キオスク上で即 MessageBox** — 無人運転中にダイアログが残り、ループが止まる。却下。

**ログだけ残す** — 現状と同じで、現場では気づかれない。却下。

**ファイル名誤りと同じ MessageBox に列挙する** — タイトル「表示期限の指定」に破損が混ざる。却下。

**再生失敗したファイルだけを記憶して知らせる** — まだ表示していない壊れたファイルを見落とす。入場時の再スキャンの方が漏れが少ない。

**動画も MediaPlayer で最後まで開けるか試す** — 非同期と待ち時間が管理画面入場を遅らせる。コンテナ不正（拡張子だけの空ファイル等）はヘッダ判定で足りる。

## 結果

`ContentFileProbe` が開けないファイルを集め、`FormatBrokenFilesMessage` が案内文＋ファイル名を返す。表示は `MainWindow.EnterAdminMode`。画像・PDF の中身破損は入場時に分かる。`ftyp` はあるがコーデックが壊れた MP4 は、再生時のスキップとログに任せ、入場時のダイアログには出ないことがある。

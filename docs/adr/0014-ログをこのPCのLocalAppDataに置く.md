# ADR 0014: ログをこの PC の LocalAppData に置く

- 状態: 有効
- 日付: 2026-09-12
- 置き換え: [ADR 0008](0008-ログを監視フォルダの親階層に出力する.md)

## 文脈

ログは監視フォルダの親へ出していた（ADR 0008）。ローカルの `D:\Signage` → `D:\logs` は電話で説明しやすかったが、次が残る。

- 共有フォルダを監視すると、親（`\\server\share\logs`）へスライド切替のたび追記する。読み取り専用の共有では失敗し、監査では書き込み回数が多いアクセスに見える
- USB を監視フォルダにすると、ログもリムーバブル側へ行く
- 管理画面にログパスを出すようになったので、「環境変数を手打ちさせる」という ADR 0008 の却下理由は弱い

## 決定

通常ログは **`%LocalAppData%\PdfSignage\logs`** に固定する。監視フォルダの場所（この PC 内 / 共有 / USB）には連動しない。ファイル名と 7 日保持は変えない。

`settings.json` の読み込み失敗だけは、従来どおり exe 横の `settings_load_error.log`（ログフォルダがまだ使えないため）。

## 理由

- コンテンツ共有を読み取り専用にできる。サイネージ PC の書き込みは PC 側に閉じる
- スライドごとの追記が共有の監査やロックに乗らない
- 監視フォルダを差し替えても、その PC の障害履歴が残る
- 実パスは管理画面に出る。探す起点は「ログフォルダ」欄でよい

## 検討した代替案

**監視フォルダの親のまま、共有のときだけ LocalAppData** — 二系統になる。USB 監視でも PC 側がよいので、最初から一つにする。

**exe 横の `logs`** — `C:\Program Files` に書けない。配布フォルダを差し替えるとログが消える。exe を USB に置くとログも USB へ行く。

**監視フォルダ直下** — `FileSystemWatcher` とコンテンツ一覧を汚す（ADR 0008 と同じ）。

## 結果

ADR 0005 の「AppData に残骸を残さない」へ、試用マーカーに続いてログも載る。フォルダ削除だけではアンインストールしきれない。

以前の `D:\logs` は自動では移さない。現場に残っていれば手で消してよい。

共有フォルダ運用で「親へログを書けない」問題（ADR 0012 が残していた課題）は、ログについては解消する。変更検知の取りこぼしは別件のまま。

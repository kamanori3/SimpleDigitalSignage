# 設計判断記録（ADR）

コードを読んでも分からない「なぜそうしたのか」を残す場所。

実装を見れば **何をしているか** は分かるが、**なぜ他の選択肢を採らなかったか** は失われる。将来「これ、普通に書き直せばいいのでは」と思ったときに、まずここを読んで、当時の制約がまだ有効かを確認する。

## 書き方

- 1 ファイル 1 判断。番号は連番で、**既存のファイルは書き換えず追記もしない**
- 判断が覆ったら、新しい ADR を起こして古い方の状態を「廃止（ADR XXXX に置き換え）」に変える
- 長さは 1 画面に収まる程度でよい。迷った選択肢と、却下した理由が書いてあれば十分

### テンプレート

```markdown
# ADR XXXX: タイトル

- 状態: 有効 / 廃止（ADR XXXX に置き換え）
- 日付: YYYY-MM-DD

## 文脈

何を決めなければならなかったか。当時の制約。

## 決定

何を選んだか。

## 理由

なぜそれを選んだか。

## 検討した代替案

採らなかった選択肢と、却下した理由。

## 結果

この決定によって受け入れたトレードオフ。将来見直すとしたらどういう条件か。
```

# ADR 0016: アプリ識別子を KS_Signage にする

- 状態: 有効
- 日付: 2026-09-18

## 文脈

コード・プロジェクト・exe の内部名が `PdfSignage` のままだった。画面上の製品名は既に「簡単！シンプル！サイネージ」にしているが、配布物や開発時の呼び方が PDF 専用に見える。識別子を揃える必要がある。

## 決定

内部識別子（プロジェクト、名前空間、exe、レジストリ、LocalAppData / ProgramData のフォルダ名、単一インスタンス Mutex、自動起動の Run 値）を **`KS_Signage`** にする。

次は変えない。

- 画面上の製品名「簡単！シンプル！サイネージ」
- アクセスキーの接頭辞 `PDS1.`（既に渡したキーが無効になるため）
- 試用マーカーの置き場所の方針（PC 側・二重書き）。フォルダ名だけ識別子に追随する

## 理由

開発・配布・現場のファイル名を同じ語にそろえる。顧客向けの呼び名は日本語のままにする（[販売基盤](../販売基盤.md)）。

## 検討した代替案

**exe だけ変えて名前空間は `PdfSignage` のまま** — 呼び方が二系統のまま残る。

**製品名まで KS_Signage にする** — 顧客向けの名前を変えることになる。しない。

**レジストリと AppData だけ旧名を残す** — 旧試用マーカーは読めるが、識別子がまた割れる。出荷前なのでフォルダ名も揃える。既存 PC の試用開始日は引き継がない。

## 結果

`%LocalAppData%\KS_Signage` と `HKCU\Software\KS_Signage` が新しい保存先。以前の `PdfSignage` 配下は自動では移さない。試用 XOR マスクも識別子に合わせるので、旧 `trial.dat` は読めない。

旧 ADR（0013 / 0014 / 0015）の本文に残る `PdfSignage` は当時の名前。パスの方針は有効なまま、フォルダ名は本 ADR が上書きする。

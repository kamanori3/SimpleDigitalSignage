# 運用ガイド（簡単！シンプル！サイネージ）

現場投入時のフォルダ運用・管理・ログ・権限の要点。

## 配布・初回セットアップ

1. `publish/PdfSignage-win-x64` フォルダ一式を現場 PC にコピー
2. `PdfSignage.exe` を起動（初回で `settings.json` が自動作成）
3. `Ctrl+Shift+M` で管理画面を開き、監視フォルダ・表示秒数等を設定
4. コンテンツを監視フォルダに配置

テンプレート: `settings.example.json`

```powershell
# 配布ビルドの作成（開発環境）
.\scripts\publish.ps1
```

## コンテンツ担当者の運用

監視フォルダ（本番例: `D:\Signage`）の**直下**にファイルを置く・削除するだけ。

| 種別 | 拡張子 |
|------|--------|
| 画像 | `.jpg`, `.jpeg` |
| PDF | `.pdf` |
| 動画 | `.mp4` |

- サブフォルダ内のファイルは対象外
- ファイル名は昇順（数字は数値として比較。例: `001`, `002`, `010`）
- 表示秒数の上書き: ファイル名**末尾**の `_数字`（5〜300。例: `案内_120.pdf` → 120 秒）。動画は再生完了まで（秒数は無効）
- 再生期限: ファイル名**末尾**の `_YYYYMMDD`（例: `案内_20260904.pdf`）。指定日当日まで再生し、翌日から対象外。動画も期限の対象
- 秒数と期限は末尾で順不同（`案内_20_20260212.pdf` / `案内_20260102_30.pdf`）。途中の `_001` などは無視
- 入力誤り（存在しない日付、日付の桁不足 6〜7 桁、秒数の範囲外、秒数や期限の重複）は再生を止めない。誤った指定だけ捨て、残りを使う。`IMG_2716.jpg` のような 4〜5 桁・9 桁以上の末尾数字は対象外（アラートしない）。詳細は [ADR 0010](adr/0010-6-7桁の末尾数字は日付の桁落ちとして扱う.md)
- 誤りは管理モード入場のたびに MessageBox で知らせる（キオスク再生中には出さない）。本文は修正案内（例: `○○_20261231`、`○○_20_20260212`）と対象ファイル名。個別の技術理由は MessageBox には出さず、ログの WARN に残す
- 壊れたファイルも再生は止めずスキップする。管理モード入場のたびに別の MessageBox（タイトル「壊れたファイル」）で対象ファイル名を知らせる。コピー途中の排他ロックは破損扱いしない。動画はコンテナヘッダ（`ftyp`）まで判定し、コーデック破損は再生時のスキップとログに任せる（[ADR 0011](adr/0011-壊れたファイルも管理モード入場時に知らせる.md)）

変更は**現在表示中のスライドが終わった後**に反映される。日付が変わって期限切れが発生した場合も同じ（次スライド境界でプレイリスト再構築）。期限切れで外したファイルはログに INFO を残す。

## システム管理者

| 操作 | 方法 |
|------|------|
| 管理画面を開く | キオスク表示中に `Ctrl+Shift+M`。ファイル名の秒数・期限に誤りがあれば、入場のたびに MessageBox（タイトル「表示期限の指定」）で修正案内と対象ファイル名を出す。壊れたファイルがあれば続けて MessageBox（タイトル「壊れたファイル」）で差し替え案内と対象ファイル名を出す |
| キオスクに戻る | 管理画面「通常モード（キオスク）に戻る」または再度 `Ctrl+Shift+M` |
| 設定を保存 | 「保存して設定する」→ `settings.json` に保存・即時反映 |
| アプリ終了 | 管理画面「アプリを終了」または管理画面を × で閉じる |

**設定を保存すると、表示は先頭のスライドから再開します。** 監視フォルダを変えていない場合も同じです。表示中の位置は保持されません。

管理画面のタイトルバーにアプリのバージョンが表示されます（`簡単！シンプル！サイネージ ver.XX.X.XX - 管理モード`）。問い合わせの際はこの値を伝えてください。

### 管理画面で設定できる項目

- 監視フォルダパス
- デフォルト表示秒数（5〜300）
- Windows 起動時の自動起動 ON/OFF
- アプリ終了時刻（日次・HH:mm）
- PC 電源オフ時刻（日次・HH:mm）
- 復帰不能時メッセージ
- ライセンス状態（表示のみ）
- アクセスキーの貼り付けと適用
- ログフォルダのパス（表示のみ）

初回起動で、その Windows ユーザーの試用 60 日が始まります。試用開始日は exe フォルダではなく、`HKCU\Software\PdfSignage` と `%LocalAppData%\PdfSignage\trial.dat` に残します（[ADR 0013](adr/0013-試用開始日はPC側に残す.md)）。配布フォルダや `settings.json` を消しても、同じユーザーでは試用は延びません。

## ログ

| 項目 | 内容 |
|------|------|
| 出力先 | この PC の `%LocalAppData%\PdfSignage\logs`（監視フォルダ・共有フォルダには書かない。[ADR 0014](adr/0014-ログをこのPCのLocalAppDataに置く.md)） |
| ファイル名 | `app_YYYYMMDD.log`（日次） |
| 保存期間 | **7 日間**（起動時・設定保存時に古いログを自動削除） |

起動・スライド切替・エラー・スケジュール実行が記録される。障害調査時は ERROR 行と前後の INFO を確認する。以前の版が `D:\logs` など監視フォルダの親へ出していたファイルは使わない。残っていれば手で消してよい。

**例外:** `settings.json` の読み込み自体に失敗した場合は、ログ出力先がまだ確定していないため、`PdfSignage.exe` と同じフォルダの `settings_load_error.log` に記録される。「設定が反映されない」「起動するたびに設定が初期値に戻る」場合はこのファイルを確認する。

## スケジュール運用（夜間停止・朝の自動起動）

1. 管理画面でアプリ終了時刻・PC 電源オフ時刻を設定（任意）
2. Windows 自動起動を ON にすると、ログオン後にアプリが起動する

典型フロー:

```text
夜: アプリ終了 →（任意）PC 電源オフ
朝: PC 起動 → Windows ログオン → アプリ自動起動 → 表示開始
```

PC 電源オフは `shutdown /s /t 0` を実行する。失敗時はログに記録される。

### 設定時刻を過ぎてから起動した場合

**その日はアプリ終了も PC 電源オフも実行されない。** アプリは「監視を始めてから設定時刻を跨いだ瞬間」にだけ動作するため、例えば終了時刻 18:00 の PC を 20:00 に手動起動しても、即座に終了することはない（翌日の 18:00 に終了する）。

臨時に電源を入れて掲示したあと確実に落としたい場合は、管理画面の「アプリを終了」を使う。

## 画面に出るメッセージの見分け方

コンテンツが表示されない状態は 2 種類あり、原因が異なる。

| 画面 | 意味 | 対処 |
|------|------|------|
| 「表示するコンテンツがありません」＋フォルダパス（小さいグレー文字） | 監視フォルダに対象ファイルが 1 つも無い。**異常ではない** | 表示されているパスが正しいか確認し、ファイルを置く |
| 復帰不能時メッセージ（既定「表示を復旧しています」・大きい文字） | ファイルはあるが、すべて読み込みに失敗した | 管理画面を開いて「壊れたファイル」ダイアログと、ログの ERROR 行でファイル名を特定し、差し替える |
| 下端の「契約期限が切れています…」帯 | 試用または契約の期限切れ。**再生は止まらない** | 届いたアクセスキーを管理画面に貼り、「アクセスキーを適用」 |

前者はファイルを置けば自動で復帰する（バックグラウンドで再スキャンを続けている）。

## 権限・環境要件

| 項目 | 要件 |
|------|------|
| OS | Windows 11（win-x64） |
| .NET | 配布版は self-contained（ランタイム同梱） |
| 監視フォルダ | 読み取り権限 |
| ログフォルダ | 書き込み権限 |
| PC 電源オフ | 通常は標準ユーザーで可。グループポリシーにより拒否される場合あり |
| Windows 自動起動 | レジストリ `HKCU\...\Run` への書き込み（標準ユーザーで可） |

### 共有フォルダを使う場合

既定（スタンドアロン）では監視フォルダに UNC とネットワークドライブを指定できない。ネットワーク商品は同じ exe の `settings.json` で `allowNetworkWatchFolder` を `true` にする（管理画面からは切り替えない）。フラグを ON にしても、共有フォルダ運用の正式サポート（変更検知の取りこぼし）は未了である。

ネットワーク共有を監視フォルダに指定する運用では、**書き込み権限などのアクセス制限は導入先の共有設定で行ってください。** アプリ側ではユーザー認証や ACL の管理は行いません。ログはこの PC へ書くため、サイネージ PC の共有権限は**読み取りのみ**で足ります。推奨は、コンテンツ担当者だけが書き込める設定です。

## 性能目標（受け入れ基準）

| 指標 | 目標 |
|------|------|
| 起動〜初回表示 | 30 秒以内 |
| スライド切替 | 3 秒以内（ログ `スライド切替: ... (Nms)` で確認） |
| メモリ | 500 MB 以下（長時間運転後） |

## 既知の制限事項

| 項目 | 説明 |
|------|------|
| Alt+Tab 完全抑制 | OS 制約により完全な抑制は不可。可能な範囲で抑制 |
| シングルディスプレイ | プライマリ画面に固定。マルチモニタの個別制御は未対応 |
| 監視フォルダ | 直下のみ。既定はこの PC 内（ローカルディスク / USB）。UNC・ネットワークドライブは `allowNetworkWatchFolder` が true のときだけ受け付ける。共有の正式サポートは未了 |
| 対応形式 | JPEG / PDF / MP4 のみ（PNG・GIF・MOV 等は未対応） |
| PC 電源オフ | ポリシー・権限により `shutdown` が失敗する環境がある |
| 自己再起動 | 再起動直後 30 秒以内の再クラッシュは再起動しない（ループ防止）。ログに「自己再起動をスキップしました」が出る |
| 二重起動 | 同一 PC で複数インスタンスは起動しない（Mutex） |
| スケジュール | 設定時刻を過ぎてから起動した日は発火しない（上記参照） |
| 設定保存 | 保存すると再生位置が先頭に戻る |
| 再生期限の反映 | 日付跨ぎ後、期限切れファイルが外れるのは次スライド境界。表示中のスライドは中断しない |
| 動画の音声 | 音量制御は未実装。音声付き動画は既定の音量で再生される |
| 配布フォルダ | 書き込み権限が必要（`settings.json` を同じ場所に保存するため）。`C:\Program Files` 配下は不可 |

## アクセスキーの発行（販売側）

現場のポータブル配布には Issuer を入れない。キーの発行はリポジトリ側で行う。

```powershell
dotnet run --project PdfSignage.Issuer -- gen-keys
dotnet run --project PdfSignage.Issuer -- issue --id C-0001 --plan standard --expires 2027-09-12 --org "団体名"
```

- 秘密鍵は `secrets/access-key-private.pem`。git に入れない。別媒体へバックアップする
- 秘密鍵を失うと新規発行できない。公開鍵を差し替えると、すでに渡したアクセスキーはすべて無効になる
- `gen-keys` のあと、標準出力の公開鍵を `PdfSignage.Licensing/AccessKeyPublicKey.cs` に埋め込み、アプリを再ビルドする（初回は実装時に埋め済み）
- 既存のキーを上書きする場合だけ `gen-keys --force`

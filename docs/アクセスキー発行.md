# アクセスキー発行（販売側）

販売側・開発側の作業手順。**現場に渡す文書（操作ガイド・運用ガイド・pptx）には書かない。** ポータブル配布にも Issuer は入れない。

方針（何をキーに入れるか、期限の起算）は [課金方針.md](課金方針.md)。実装の型は [設計書.md](設計書.md)。

---

## 1. 普段やること（発行）

リポジトリのルートで実行する。秘密鍵は `secrets/access-key-private.pem`（git 対象外）。無いときは §3。

```powershell
dotnet run --project KS_Signage.Issuer
```

フォームが開く。契約の通し番号・プラン・期限（組織名は任意）を入れて「アクセスキーを発行」する。できたキーはクリップボードへコピーされ、同じ画面の一覧にも出る。改行を入れずにメールへ貼る。顧客には管理画面（`Ctrl+Shift+M`）の **ライセンス等** タブへそのまま貼って「アクセスキーを適用」と案内する。

発行履歴は `secrets/issued-access-keys.json`（git 対象外）。再署名すると文字列が変わるので、送ったキーそのものを残す。

| 項目 | 必須 | 内容 |
|------|------|------|
| 契約の通し番号 | 必須 | 問い合わせ照合用。例: `C-0001`。台帳と揃える。フォームは次の番号を入れる |
| プラン | 必須 | 標準（契約上 5 台）またはサイト（台数無制限）。アプリは台数を数えない |
| 契約期限 | 必須 | その日の終わりまで有効。フォームの初期値は発行日＋1 年 |
| 組織名 | 任意 | 問い合わせ時に管理画面へ出る |

同じ組織の全 PC に同じキーでよい。フォルダ複製でも動く。

コマンドラインでも出せる（フォームと同じ台帳に残る）。

```powershell
dotnet run --project KS_Signage.Issuer -- issue --id C-0001 --plan standard --expires 2027-09-12 --org "団体名"
```

| 引数 | 必須 | 内容 |
|------|------|------|
| `--id` | 必須 | 契約の通し番号 |
| `--plan` | 必須 | `standard` または `site` |
| `--expires` | 必須 | 契約期限 `yyyy-MM-dd` |
| `--org` | 任意 | 組織名 |
| `--private-key` | 任意 | 省略時は `secrets/access-key-private.pem` |

### 期限の決め方

| 状況 | 新しい期限 |
|------|------------|
| 新規（試用中・試用切れ） | 発行日（または入金日）+ 1 年 |
| 期限内の更新 | いまの期限の翌日起点で 1 年 |
| 期限切れ後の更新 | 発行日（または入金日）から新たに 1 年。切れ期間は遡らない |
| 導入トラブルの無償延長 | 短い期限（例: 30 日）のキーを新規発行。アプリ内にリセットボタンは無い |

発行したキー・通し番号・プラン・期限・組織名はフォームの一覧と `issued-access-keys.json` に残る。連絡先・入金日・メモは別途台帳へ書く。

## 2. 問い合わせが来たとき

オフラインなので、遠隔で期限を書き換えることはできない。新しいキーを出して貼ってもらう。

| 連絡 | やること |
|------|----------|
| キーが通らない | コピー漏れ・改行・旧ビルド（公開鍵が違う）を疑う。正しいキーを再送。旧公開鍵の exe なら、いまの公開鍵でビルドし直した配布物が必要 |
| アプリを差し替えたらキーが消えた | 現場の `settings.json` が残っているか確認。フォルダごと入れ替えると消える。上書きして残していれば再入力は不要 |
| 入金したのに帯が出る | 新しいキーが未適用。ライセンス等タブへ貼る案内 |
| 試用が終わっている | 同じ PC では試用開始日は延びない。契約キー、または短い無償キーを出す |
| 期限を伸ばしたい | 新しい期限のキーを出す（これが更新） |

管理画面の **ライセンス等** タブに状態・期限・契約番号・組織名が出る。電話ではこれを読んでもらう。

## 3. 初回だけ：キーペアを作る

秘密鍵が無いとき、または公開鍵を入れ替えるときだけ。**既存のアクセスキーはすべて無効になる。** 現場の exe も再配布が必要。

```powershell
dotnet run --project KS_Signage.Issuer -- gen-keys
```

- 秘密鍵: `secrets/access-key-private.pem`。標準出力には出ない。git に入れない。別媒体へバックアップする
- 公開鍵: 標準出力と `secrets/access-key-public.pem`
- 標準出力の公開鍵を `KS_Signage.Licensing/AccessKeyPublicKey.cs` に埋め込み、アプリを再ビルドする
- 既存ファイルを上書きするときだけ `gen-keys --force`

秘密鍵を失うと新規発行できない。公開鍵だけ差し替えても、古い秘密鍵で署名したキーは通らなくなる。

---

## 4. やってはいけないこと

- 操作ガイド・運用ガイド・配布フォルダに Issuer や `gen-keys` を書く
- 秘密鍵を git・メール・チャットに載せる
- 理由なく `gen-keys --force` する（全顧客のキーが死ぬ）
- 現場 PC で発行する（秘密鍵を現場に置かない）
